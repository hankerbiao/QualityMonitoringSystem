# 质量数据整合系统设计文档

## 1. 项目概述
本项目旨在将四个分散的质量数据子系统整合到一个统一的前端系统中，为管理层和质控团队提供一站式的数据查看和分析入口。

核心模块包含：
1. **RTY 整机综合直通率**
2. **LRR 部件故障率**
3. **DOA 报修率**
4. **MFR 月化故障率**

当前第一阶段主要完成基础框架搭建以及【RTY 整机综合直通率】模块的前端页面设计与交互实现。

## 2. 技术栈架构
- **前端框架**：React 19 + TypeScript
- **构建工具**：Vite
- **路由管理**：React Router DOM v7
- **UI 组件库**：shadcn/ui (Tailwind CSS 驱动，非传统组件库，代码更加现代化、易定制)
- **CSS 框架**：Tailwind CSS v4
- **图表库**：Recharts (ComposedChart 双轴图表)
- **图标库**：Lucide React
- **数据流管理**：React Hooks (useState, useEffect, useMemo 等)
- **Excel 导出**：xlsx 库
- **AI 助手**：基于规则引擎的模拟智能助手

## 3. 目录结构与分层设计
系统采用清晰的分层架构，以确保代码的高可读性和可扩展性：

- `src/api`：数据接口层（目前使用 Mock 数据封装，保留真实的 Promise 异步结构，方便后续直接替换真实接口）
- `src/components`：全局和业务相关的可复用组件
- `src/components/ui`：项目内复用的基础 UI 组件（例如 Modal、LoadingSpinner）
- `src/pages`：页面级组件
  - `Home`：系统入口页，展示四个子模块卡片
  - `RTY`：RTY 整机综合直通率业务页
- `src/types`：全局 TypeScript 类型定义，用于规范前后端接口数据结构
- `src/lib`：工具函数，如样式合并（`cn`）等

## 4. 首页 (Home) 设计
系统入口页已进行全新改版升级，整体采用亮色主题，符合中后台企业级数据看板风格。

### 4.1 核心价值定位
- 首页头部明确核心定位：基于 5000 公司销售订单数据，全面打通 MES、SAP、SCS 等核心系统，提供端到端的整机与部件质量监控、深度分析与自动化预警。

### 4.2 模块导航与介绍设计
首页采用 Bento Grid 风格展示四大核心质量模块，文案精准对齐底层数据源与计算逻辑：
1. **RTY (整机综合直通率)**：依托 MES 销售订单数据，监控普通及复合机型的整体与过站直通率。提供多维度(基地/客户/订单)数据穿透下钻、实际达成与指标对比，并支持邮件自动化预警机制。
2. **LRR (工厂阶段部件故障率)**：基于 MES 生产与维修数据，精准统计工厂阶段各部件维度的故障率。支持按机型、部件类型、PN等维度深层剖析，锁定缺陷根因。
3. **DOA (开箱报修与换件率)**：联动 SAP 发货数量与 SCS 报修数据，追踪设备开箱即损状态。细分“DOA报修率”与纯硬件更换的“DOA换件率”。
4. **MFR (现网月化故障率)**：结合 SCS 换件记录与在保设备体量，计算产品现网月化故障率，动态呈现产品在全生命周期的现网质量表现。

## 5. RTY 模块详细设计
### 5.1 页面布局
- **整体风格**：页面采用企业级数据平台风格（类似中后台系统），减弱圆角幅度，采用高屏效、更紧凑的间距和严肃的色彩搭配，适配中高层管理人员的审美需求。
- **顶部过滤条件区**：采用自适应弹性布局以最大化利用水平空间。
  - 统计方式：[整体直通率, 过站直通率]
  - 计算方法：[普通机型, 复合机型]
  - 基地：[天津, 昆山, 桐乡, 大同]
  - 客户、销售订单、整机序列号。
  - 页面标题显示”数质看板 — RTY 整机综合直通率”
- **看板快捷切换**：页面顶部右侧提供快速切换看板导航，支持 RTY/LRR/DOA/MFR 模块切换（未实现模块显示为灰色不可点击）
- **主数据展示区**：展示 RTY 统计表格。
  - 字段包含：时间、机型、客户、基地、故障数量、投入数量、直通率、**直通率指标**、**达成状况**。
  - **表格排序**：支持按时间、故障数量、投入数量、直通率进行升序/降序排序
  - **Excel 导出**：支持选择导出字段，生成 xlsx 文件
  - **机型指标配置**：通过系统配置管理模块（统一移出），支持按不同机型单独维护考核的”直通率标准 (%)”。
  - **动态应用指标**：实时动态应用到表格数据的”直通率指标”对比中。
  - **达成状况**：根据计算得出的”直通率 (RTY)”与设定的”直通率指标”进行对比，自动判定并渲染”达成（绿）”或”未达标（红）”标签。
- **周期统计面板**：在”周期统计”功能下。
  - **周期统计概览**：面板上方多列网格展示关键指标（累计投入数量、综合平均直通率、总故障数、产量最高月份、高风险机型、最佳表现机型）。精简并移除了”历史告警触发次数”以及内嵌的管理链接。
  - **生产量及直通率趋势图与统计表**：通过图表（条形+折线图双轴）展示月度聚合的 RTY 变化趋势，下方附带直通率统计报表，直观高亮低于指标的月份数据。

### 5.2 交互设计
- **数值穿透查询**：表格中的”故障数量”和”投入数量”支持点击。点击后弹出明细弹窗，可展现对应维度的底层详情（含具体序列号和故障原因等）。
- **表格排序交互**：点击表头字段可切换排序方向，显示升序/降序箭头图标
- **导出交互**：点击导出按钮弹出字段选择面板，勾选需要导出的字段后确认导出

## 6. 系统配置管理 (Settings)
- 提取并独立设立了统一的"系统配置管理"中心（通过首页入口进入）。
- **MES 系统接入**：支持配置读取 MES 数据的 API 账号与密码，支持密码明文显示/隐藏切换。
- **RTY 机型指标配置**：统一维护各机型的直通率达标标准线。
- **邮件预警规则配置**：
  1. **统一的统计时间范围 (业务周期)**：监控统计范围设为**近半年(6个月)**或**近一年(12个月)**。
  2. **预警触发逻辑**：核心规则：`当前周期内某一机型的实际直通率 (RTY) < 该机型设定的直通率指标`。触发后生成系统告警。
  3. **告警配置设计**：提供周期直通率邮件监控的一键开关。支持配置多个接收人邮箱，并可勾选在邮件中附带数据明细。
- **AI 模型配置**：支持配置 API 地址、模型 ID、API Key、Max Tokens。

## 7. OA 单点登录 (Auth)
- **登录入口**：ProtectedLayout 拦截所有未登录访问，重定向到登录页。
- **双 Token 机制**：
  - **access_token**：短期令牌，有效期 15 分钟，用于所有 API 请求鉴权
  - **refresh_token**：长期令牌，有效期 30 天，用于 access_token 过期后换发新令牌
- **OA 回调**：支持两种回调格式：
  - GET: `?status=success&access_token=xxx&refresh_token=xxx&expires_in=900` (OA 直接重定向)
  - POST: `?status=success&payload=JWT` (前端 JS 调用，后端返回双 token)
- **Token 存储**：
  - access_token + expires_in → localStorage (`qualiboard-access-token`, `qualiboard-token-expiry`)
  - refresh_token → sessionStorage (浏览器关闭后清除，30 天有效期以服务端为准)
- **自动刷新**：前端在以下时机自动刷新 access_token：
  - 每次 API 请求前检查，若剩余有效期 < 60 秒则先刷新
  - 收到 401 响应时立即刷新
- **前端处理**：存储 Token，等 `setUser()` 完成后再跳转，避免 ProtectedLayout 提前 redirect。
- **后端 Session**：MongoDB sessions 集合存储 refresh_token + access_token，TTL 30 天。

## 8. AI 智能助手
- **悬浮球式交互**：右下角固定位置显示 AI 助手悬浮按钮，点击展开对话窗口
- **可见性控制**：支持隐藏/显示切换，状态保存至 localStorage
- **快捷问题**：初始状态显示建议问题列表（趋势分析、达成率、故障分析、改善建议）
- **模拟回复**：基于规则引擎的模拟 AI 回复功能，回复内容针对 RTY 数据分析场景
- **对话界面**：用户/助手双角色消息气泡，支持 Enter 发送
