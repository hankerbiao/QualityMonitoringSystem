## OA 登录 前后端代码评审
结论：仓库无后端源码，前端经 vite proxy 把 `/api` 转到 `localhost:8000`，真实认证后端是外部 `tl.cooacloud.com` 的 Spring 服务。
主要问题（详见交付的评审说明）：
- **P0 阻断**：`AuthContext.tsx` OA 回调成功/失败后都未 `setLoading(false)`，导致 `ProtectedLayout` 一直 `return null` → 登录后白屏。
- **P1 安全**：token 出现在 URL query（`?token=`）；token 存 localStorage + `X-Session-Token` 头（XSS 可盗）；`OA_LOGIN_BASE_URL` 硬编码 `http://`（HTTPS 下 mixed-content 被拦）。
- **P2 契约**：`authApi.ts` 的 `submitOALogin`/`POST /api/auth/oa/callback` 是死代码，与前端实际采用的「URL 取 token」契约矛盾；无全局 401 处理/自动登出；`next` 深链失效+开放重定向隐患；登录失败无提示。
- **P3**：`AuthContext` 留调试 console.log；认证态依赖模块级单例 `sessionToken`；`ProtectedLayout` 加载态返回 null。
- 待办：询问用户是否直接修 P0+P1（不依赖后端契约的部分）。

- **P0 白屏修复**：`AuthContext.tsx` 的 OA 回调成功/失败分支都补 `.finally(() => setLoading(false))`；失败分支额外 `clearSessionToken()+setUser(null)`。已消除登录后白屏。

## 全局 401 自动登出（已实施，纯前端）
- `authApi.ts`：新增统一请求封装 `apiFetch()`（自动注入 `X-Session-Token`，遇 401 触发已注册 handler 并 throw 'UNAUTHORIZED'）；`withAuthHeaders` 改为返回 `Headers` 对象（更健壮，支持任意 HeadersInit）；`getCurrentUser` 改走 `apiFetch`。新增 `registerUnauthorizedHandler()` + 模块级 `unauthorizedHandler`（默认 noop）做解耦回调。
- `AuthContext.tsx`：挂载时 `useEffect(() => registerUnauthorizedHandler(logout), [logout])`，把 `logout` 注册为全局 401 处理器。
- `authApi`（纯模块、无 React 依赖）与 `AuthContext` 通过回调解耦，互不直接耦合。
- 验证：`npm run lint` 与 `npm run build` 均通过。

## 认证安全加固改造方案文档
- 新增 `docs/auth-security-hardening.md`：与后端对齐用的改造方案，覆盖 P1 安全问题（Token 进 URL、localStorage 明文、无过期）。
- 方案：OAuth2 授权码模式（回跳带 code 而非 token，前端 POST /api/auth/oa/callback 换会话）+ HttpOnly/Secure/SameSite Cookie 下发会话（前端不再存令牌明文）+ 阶段二 token 过期/刷新（复用 apiFetch 401 钩子）。
- 含前后端接口契约、前端(authApi/AuthContext/LoginPage/apiFetch)与后端改动清单、双轨灰度迁移、验收标准、待确认事项（OA 平台是否支持授权码、网关是否透传 Set-Cookie）。
- 注：此前删除的 `submitOALogin` 骨架在文档中建议复用为 `POST /api/auth/oa/callback`。

## 会话存储抽象层重构（sessionStore，为后续 Cookie 化铺路）
- 新增 `src/api/sessionStore.ts`：定义 `SessionStore` 接口（`get/set/clear`）+ `LocalStorageSessionStore` 实现 + 默认导出 `sessionStore` 实例；文件内注释给出阶段一（HttpOnly Cookie）`CookieSessionStore` 切换示例（届时只换默认实例，业务代码不动）。
- `authApi.ts`：移除模块级 `sessionToken` 单例与 `restoreSessionTokenFromStorage`，改为 `getSessionToken()/setSessionToken()/clearSessionToken()` 走 `sessionStore`；`withAuthHeaders` 改读 `sessionStore.get()`。
- `AuthContext.tsx`：import 由 `sessionToken`/`restoreSessionTokenFromStorage` 改为 `getSessionToken`；`restoreSession` 去掉 `restoreSessionTokenFromStorage()` 调用，直接用 `getSessionToken()` 预判断，不再依赖模块级单例。
- 验证：`npm run lint` 与 `npm run build` 均通过；grep 确认无旧 `sessionToken` 变量/`restoreSessionTokenFromStorage` 残留引用。
- 价值：后续阶段一（Cookie 化）只需替换 `sessionStore` 默认实例，authApi/AuthContext 零改动（仅「是否已登录」预判断在 Cookie 方案下需改为由 /api/auth/me 判定，已在方案文档阶段一清单规划）。
