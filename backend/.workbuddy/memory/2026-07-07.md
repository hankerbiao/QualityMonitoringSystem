# 2026-07-07

## 后端代码结构评审 (code review)
评审了 `backend/` 的代码组织清晰度，主要发现：
- 目录分层（api/services/schemas/models/db/core）理念清晰，但**实现与文档严重脱节**：README/AGENTS.md 描述的 `/api/rty/{id}/defects`、`/{id}/inputs`、`/cycle-stats`、`/api/ai/analyze` 在代码中并未实现（代码只有 `/api/rty/list` 和 `/api/ai/chat`）。
- `app/models/documents.py` 的 DB 文档模型（RTYDocument 等）几乎全部是死代码，仅 `Collections` 被使用；实际 schema 定义在 `app/schemas/`。两处 schema 会漂移。
- 路由层直接调用 `get_database()` 做原始 CRUD，缺少 repository/data-access 层；`settings.py` 549 行胖路由。
- `auth_service.py` 放在 `app/` 根而非 `app/services/`，与主服务布局不一致。
- `app/core/logger.py` 的 `@audit_log` 装饰器与 `NoOpAuditLogger` 均未接入任何路由（审计能力建而未用）。
- `init_db.py` 与 `init_default_settings.py` 内容完全相同（重复脚本），Dockerfile 用 init_db.py。
- `schemas/common.py` 的 `PaginatedResponse`/`ErrorResponse`、`schemas/rty.py` 的 `*Create`/`*InDB` 等样板模型从未被引用。
- `config.py` 硬编码了 JWT 密钥（OA_JWT_SECRET），属安全隐患。
- `rty.py` 的 `serial_number` 查询参数声明但未在查询中生效（死参数）。
