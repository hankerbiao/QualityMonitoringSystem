## 修复语音识别结果不填充输入框的 Bug

- **根因1 — WS 时序问题**：`start()` 中 `ws.connect()` 后立即 `audioCapture.acquire()`，但 WS 尚未完成握手（readyState ≠ OPEN），音频帧被 `send()` 的 readyState 检查静默丢弃 → 后端收不到音频、无识别结果
- **修复**：`useVoiceWebSocket.connect()` 改为返回 `Promise<WebSocket>`，在 `onopen` 时 resolve；`useVoiceRecognition.start()` 改为 `await ws.connect()` 后再 `acquire()`，与 `test.html` 行为一致
- **根因2 — 文字无回显**：`AIAssistant.handleVoiceResult` 仅在 `isFinal=true` 时写 `setInput`，识别过程完全不可见
- **修复**：`handleVoiceResult` 不再区分 isFinal，统一 `setInput(text)`；`VoiceInput` 状态条在 listening 状态时展示 `interimText` 实时文字

## 修复"卡在 connecting"问题

- **根因**：上一轮修复引入新问题。`onCleanedUp` 在 2500ms 之后才执行，期间再次点击 start 重新建立连接 → 旧 timer 触发回调 → 把新会话的 `isActiveRef` 设为 false → 新连接的 `onOpen` 被守卫拦截 → 永远 `connecting`
- **修复 1（WS 层 — generation 隔离）**：`useVoiceWebSocket` 引入 `generationRef` 计数器，每次 `connect()` 递增；所有回调（onopen/onmessage/onerror/onclose）和 cleanup timer 都验证 `myGeneration === generationRef.current`，旧连接的回调自动失效
- **修复 2（Core 层 — sessionToken 隔离）**：useVoiceRecognition 引入 `sessionTokenRef`，每次 `start()` 递增；`stopCleanup` 接受 token 参数，`onCleanedUp` 仅在 token 未变时才重置 isActiveRef/setStatus
- **修复 3（移除 onOpen 守卫）**：`onOpen` 不再检查 `isActiveRef`，避免被旧 cleanup 错误地阻断新连接
- **修复 4（卸载保护）**：useEffect 卸载时递增 sessionToken，让挂起的 cleanup 回调全部失效

### 修改文件
- `src/hooks/voice/useVoiceWebSocket.ts` — 引入 generationRef 隔离连接会话
- `src/hooks/useVoiceRecognition.ts` — 引入 sessionTokenRef 隔离清理回调

## 修复识别效果不如 test.html 的 4 个关键问题

- **根因1 — isActiveRef 守卫丢弃服务端最终结果**：`stop()` 立即设置 `isActiveRef=false`，但 `ws.disconnect()` 发送 end 后服务端返回的 `is_final=true` 结果被 `onMessage` 守卫拦截丢弃
  - 修复：`stop()` 不再设置 `isActiveRef=false`，移除了 `onMessage`/`onError` 的 `isActiveRef` 守卫；`isActiveRef` 改为在 `ws.disconnect(onCleanedUp)` 回调中设置（CLEANUP_DELAY=2500ms 后）
- **根因2 — 停止顺序错误**：旧顺序先发 end 再停麦克风，导致最后几帧音频未送达
  - 修复：`stopCleanup` 改为先 `audioCapture.release()` 再 `ws.disconnect()`
- **根因3 — handleVoiceResult 忽略 isFinal**：AIAssistant 不区分 interim/final，即使最终结果到达也无法触发自动发送
  - 修复：`handleVoiceResult` 在 `isFinal=true` 且文本非空时自动调用 `sendMessage`
- **根因4 — 静音检测过于激进**：`SILENCE_TIMEOUT=3000` + `SOUND_AMPLITUDE_THRESHOLD=0.01` 在自然停顿中频繁触发自动停止
  - 修复：`SILENCE_TIMEOUT` 3000→8000ms；`SOUND_AMPLITUDE_THRESHOLD` 0.01→0.005
- **其他**：`useVoiceWebSocket.disconnect()` 增加 `onCleanedUp` 可选回调参数 + `cancelCleanupTimer()` 防止重复调用；`useEffect` 卸载清理不再调用 `ws.disconnect()` 改为直接释放音频资源

- `src/hooks/useVoiceRecognition.ts` — 移除 guards、调整 release 顺序、ws.disconnect 回调管理 isActiveRef

## 修复最后一个字丢失 + 识别结果累加

- **最后一个字识别不全**：`stop()` 立即 `releaseAudio()` 断开 ScriptProcessor，不满 4096 样本(256ms)的最后一帧尾音来不及触发 onaudioprocess 发出就丢了
  - 修复：`stop()` 改为先继续采集 300ms（`STOP_TAIL_DELAY`）让最后一帧凑满发出，再 `releaseAudio()` + 发 end；新增 `stopTimerRef`，`start()`/卸载时 clearTimeout 防止延迟回调干扰新会话
- **识别结果要累加不清空之前输入**：之前 `handleVoiceResult` 直接 `setInput(text)` 覆盖了输入框已有内容
  - 修复：AIAssistant 新增 `inputBaseRef`，`handleToggleVoice` 开始录音时记录 `inputBaseRef.current = input`；`handleVoiceResult` 改为 `setInput(inputBaseRef.current + text)`，识别结果追加到已有内容之后

## 修复"停止后只剩最后一个字"

- **根因**：服务端 is_final 消息的 text 字段实测只是末尾片段（如"吗"），而 onmessage 用 `data.text || accumulatedRef` 直接覆盖，丢掉了流式累加的完整文本
- **修复**：
  1. is_final 时优先用 `accumulatedRef`（流式累加完整结果），仅当 `data.text` 更长（2pass 纠正完整句）时才采用 data.text
  2. 增量文本兼容 delta/cumulative 两种协议：`data.text.startsWith(accumulated)` 则替换，否则累加
  3. 去掉上一轮引入的 stop 300ms 延迟（`STOP_TAIL_DELAY`/`stopTimerRef`），回到立即停麦克风+发 end，避免尾音被服务端单独识别成一个 is_final 片段
- **教训**：上一轮"最后一个字识别不好"其实也是同一个 data.text 覆盖 bug，而非 ScriptProcessor 丢帧；当时误判加了 300ms 延迟反而引入新问题
