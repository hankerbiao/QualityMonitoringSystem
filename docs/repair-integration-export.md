# 维修物料整合导出

RTY 首页、RTY 详情和工位过站直通率的导出共用后端整合服务。
首页保留趋势汇总，工位页保留透视表；随后是销售订单、维修故障明记录，
以及每个机型一个统计页。机型统计页使用中文表头，不设置黄色填充。

## 数据与计算

- 筛选条件决定销售订单范围，日期沿用订单计划开始时间 GSTRS。
- 按选中生产订单关联维修，复合机型保留既有父子机绑定关系。
- 维修时间不参与筛选、关联、排序、去重或汇总。原始维修表仍按源字段保留原值。
- 分组键为机型、维修维度3、物料号；不良现象和描述不拆分统计组，而是去重后换行。
- 物料按 ZCCLH、MATNR、RECORD01REPAIRM 顺序取第一个有效值，数字料号去掉 SAP 前导零。
- 每条维修在每个关联机型内计一次，输出 `料号*n`，G 列保留数值计数。
  同一条子件维修绑定多个机头时不重复增加物料计数；J 列按绑定后的机头 SN 去重。
- G 列表头为“部件故障计数”，每个机型统计页按此列降序排列，排序后重新生成序号。
- 物料描述与选用料号对应时才沿用维修描述，也补充发料记录描述。
- H 列按机型内全部选中订单的同料号 MENGE_A 求和，包含冲销负数；
  不限制发料日期，也不再乘生产数量。按发料记录唯一 ID 去重，不合并真实的多条发料。
- K 列按去重生产订单汇总 GAMNG，与独立整合脚本默认口径一致；
  首页趋势汇总仍保留原有 WMENG 产量口径。
- I=G/H、L=J/K，以 Excel 公式和数值缓存共同保存，显示两位小数的百分比。
- 缺少料号、SN、数量、订单发料记录时输出明确提示，不把未知数量当作零。
  无维修的机型仍保留一行，维修数及 SN 数为零。
- 同一生产订单出现不同机型、销售订单、工厂或数量时终止导出，避免混合数据源误加。

## 查询与缓存

业务计算位于质量系统后端，不移动到数据网关，不保存原始发料副本。
两个看板和不同筛选范围可以复用同一生产订单的发料汇总。

1. 查询网关 `/api/data-status`，取得 `bomPostingsLastSyncedAt`。
2. 以“计算规则版本、网关地址、发料同步版本、标准化生产订单”为缓存标识。
3. 先读取最多 2048 个条目的内存缓存，再读取 MongoDB 压缩汇总缓存。
4. 未命中的订单通过网关完整分页读取，本进程最多同时处理 16 个订单；
   HTTP 请求仍受共享网关客户端 32 个连接限制。相同进程内的重叠请求合并读取。
5. 按订单汇总后即丢弃原始发料行，只缓存数量、描述、关联销售订单和记录数。
6. 版本有效时缓存最长 24 小时；同步版本改变后立即使用新缓存标识。
   MongoDB 的 `repair_material_usage_cache.expiresAt` TTL 索引负责清理过期汇总。
7. 发料同步版本不可用或同步进行中时，仅使用 10 秒内存缓存，不读写持久缓存。
8. 一次导出结束前再次检查发料同步版本，发生变化则终止并要求重新导出。

MongoDB 缓存供多个进程和后端重启后复用；同一时间不同进程首次查询时，
仍可能各自读取数据源。内存合并与并发限流的范围是单个后端进程。
缓存存储故障只导致重新读取网关，不返回过期结果；数据源故障、缺页、
唯一 ID 冲突或异常数量会终止导出，不下载部分 Excel。

单个订单最多召回 250,000 行，一次导出最多累计 1,000,000 条匹配发料记录；
超过限制要求缩小筛选范围。后端日志记录订单数、源读取数、缓存命中数、发料行数和耗时。

## 网关后续扩展

当前部署的 `POST /api/exports/rows` 支持 orders、faults、bindings；
实测传入 bom 返回 `400 unknown export resource`，因此本次不依赖不存在的批量通道。

当前 `/api/data-status` 单次实测耗时约 7～8 秒，导出前后检查约占 15 秒。
若要将命中缓存的导出进一步降至秒级，数据源需提供轻量的发料同步版本接口，
或在发料同步完成后通知品质系统更新版本。单纯增加并发无法消除这部分耗时。

后续可增加发料批量原始读取：POST 传入生产订单列表，按标准化生产订单精确匹配，
返回记录 ID、AUFNR_1、VBELN_EX、MATNR、MENGE_A、MAKTX 及完整性信息。
超限拆批，业务汇总仍由品质系统完成。接入后可替换缓存未命中时的逐订单查询，
保留本次的计算逻辑、共享缓存和完整性检查。

## 验证

- 后端验证分组、三物料字段优先级、重复维修、SN 去重、父子机映射及异常分母。
- 验证接口权限、全部筛选条件、缓存命中、同步失效、持久缓存复用和并发上限。
- 验证前端两个导出入口追加机型页，以及中文表头、公式、零值、缺项和工作表名称冲突。
- 同一份原始 Excel 的整合数据与独立脚本结果逐分组、逐字段比较。
  示例缺少原始依据的 `6210 C21 / 更换内存 / B5000112*2` 不补造。

2026-10-16 实测原始样本包含 55 个订单、233 条维修，5 个机型；
其中 53 个订单需要读取发料，实际匹配 4,259 条发料。统计输出 116 个维修分组，
另保留 1 行无维修机型，共 117 行，与独立脚本结果逐字段比较无差异。

| 整合步骤 | 实测耗时 |
| --- | ---: |
| 首次读取，16 个订单并发 | 89.88 秒 |
| 内存缓存命中 | 15.13 秒 |
| 清空内存后，MongoDB 缓存命中（两次） | 14.66 / 18.26 秒 |

以上包含同步状态检查和机型汇总，不包含看板原有的订单、维修查询及浏览器下载。
`整合/系统整合验证.xlsx` 由实际前端导出模块生成，保留原始样本三张数据页；
225 个有效比例公式及其缓存值校验通过。与示例比较 51 项检查无失败，
1 项原始数据与示例冲突，详见同目录 `系统整合验证_对比报告.md`。
