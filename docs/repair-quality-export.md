# 维修质量透视导出

维修质量透视默认状态为“仅管理员可见”，首页、路由、看板切换器及维修分析、
筛选项、导出接口均遵循该状态。线上升级时仅设置此看板的状态，不覆盖其他配置。

右上角导出按钮与 RTY、工位过站看板保持相同位置和样式，手机端显示下载图标。
按最近一次成功查询的条件导出，不使用尚未提交的筛选值；加载中、导出中、
无维修 SN 或重置后禁用。接口失败时不生成部分文件，保留看板结果并允许重试。

| 工作表 | 内容 |
| --- | --- |
| 维修质量透视表 | 客户、基地、维修 SN、首修通过率，以及 1–8 次和 9 次以上的数量、占比 |
| 销售订单 | 复用 RTY、工位过站的 18 列中文表头、列顺序、列宽与自动筛选 |
| 维修故障明记录 | 复用 RTY、工位过站的 35 列中文表头、原始字段与空值处理 |

汇总页比例以数值保存，显示两位小数百分比。最后一行是总体去重 SN 数据，
不是可重叠客户/基地分组的简单求和。原始页保留前导零、数值零及同 SN 的多次维修。

接口 `GET /api/rty/repair-quality/export` 使用维修看板权限与基地权限，
接收 dateFrom、dateTo 和重复的 productModels、customers、bases 参数。
与维修看板共用数据读取流程：按订单 ZDATE_STARTED 及机型、客户、基地选订单，
再关联维修 SN 的完整生命周期记录，不套用 RTY 的 GSTRS 日期或订单类型排除规则。
仅消除重复的同源维修记录，不按 SN 合并原始维修行。受基地权限限制的用户不导出
权限范围外订单的生命周期维修明细。订单包装数量复用 RTY 的过站计数流程。
原始订单/维修读取不完整或超过现有上限时整体失败，不截取数据导出。
